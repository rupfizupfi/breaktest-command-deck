# Decisions taken

This file records **what was decided and what was rejected** — the
reasoning that would otherwise be lost, since the reference docs state
only the conclusion.

Each decision's consequences live in the doc that owns the topic; see
[`../../OPEN-QUESTIONS.md`](../../OPEN-QUESTIONS.md) for what is still
open.

---

## Deployment topology — the decision that reframed the others

`cms` is deployed to a **cloud host**; `command-deck` runs on the
**machine physically wired to the test bench**, because it needs local
USB/serial access. The deck connects to the **cloud database**, so there
is one authoritative dataset rather than a sync problem.

This was not recorded anywhere before, and several earlier notes read
differently because of it:

- "Port 8043 collision between profiles" was never a collision — the
  profiles never share a host.
- "Single-tenant appliance, ownership is cosmetic" is wrong for the cloud
  cms, which needs real per-user isolation. It remains right for the
  deck's live telemetry topics, which serve one machine.
- The tester now needs network reachability to the cloud host in order to
  run a test at all. That dependency has no mitigation yet (OQ-61).

## Rejected, with the reason

| Proposal | Rejected because |
|---|---|
| Adopt Flyway | One cloud CMS plus one tester. Schema changes are infrequent and nobody needs to replay a migration history. Accepted cost: column renames and data migrations are manual. Revisit if the deployment becomes multi-instance. |
| Extract a `:shared` Gradle module | `:command-deck` genuinely *is* "cms plus hardware control", so being a runtime superset is the correct shape, not a smell. The deployment split doesn't change what code each side needs. |
| Rename `SettingRepository` | It is a repository in the DDD sense. The store being `settings.json` rather than a table doesn't change that. |
| Restrict which Hilla services ship in the deck bundle | Deck is the full application by design. Role annotations are the access control, not packaging. |
| Authenticate `/api/**` | The REST surface is deliberately anonymous — file upload/download and the hardware button box call it without a session. Accepted cost: file upload/download is unauthenticated, and nothing owner-scoped may ever be added under `/api/**`. |
| Per-user filtering on STOMP topics | One deck instance drives one tester, so live force readings are legitimately shared between everyone watching that machine. Would need revisiting if a deck ever fronted multiple testers. |
| Pin the Postgres image | Track upstream; handle a breaking major bump manually if it happens. |
| Fail fast without a mounted TLS cert | The self-signed cert generated by `startup.sh` is the intended operating mode — the tester is reached over a trusted local network. |
| Move `startup.sh` out of `cms/` | `:cms` is already a hard Gradle dependency of `:command-deck`, so one shared entrypoint script matches the module relationship. |
| npm/yarn workspaces | `pnpmEnable = true` already hard-links from a shared store, so duplicated `node_modules/` trees no longer cost duplicated disk. |
| Make `TestParameter.type` an enum | Users define their own parameter types through the UI and only three drive the runner. The free-form column is the feature. What needs fixing is the *silence* when an unrunnable type is used (OQ-35). |
| Migrate profile pictures to `FileMetadata` | The feature is being removed instead. |
| Bidirectional route merge | The cloud cms has no reason to know about hardware routes that only work on the tester. |
| A shared-components package for `LogComponent` | Follows from keeping cms as the shared base — a direct cross-module import is consistent with that. |

## Accepted with a known cost

| Decision | Cost accepted |
|---|---|
| Keep `ddl-auto=update` | Manual schema surgery on the live database. Hibernate adds columns but never removes or renames. |
| Keep `lib/usbmodbus.jar` out of the repo | Licence forbids redistribution. A fresh clone builds without it but cannot drive the machine; mitigation is documentation, still owed (OQ-43). |
| Fully untrack `generated/` | Anything building the frontend must run the Hilla generator first, including CI. |
| Reconnect rather than abort on load-cell loss | A test can now contain a gap in its data. The acceptable window and how the result records the gap are unspecified (OQ-45). |
| Leave `optimizeBundle` off | Possibly a larger production bundle than necessary. Measure before flipping (OQ-16). |
| No frontend test framework | `mergeRoutesArrays` stays unguarded by tests; a comment at the merge site is the substitute (OQ-19). |
