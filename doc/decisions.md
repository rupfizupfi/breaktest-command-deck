# Decisions

What was decided and what was rejected, with the reasoning the reference docs
leave out. **Belongs here:** a decision together with its rejected alternative
or its accepted cost, dated. **Does not:** plans, sketches and audits — those
are process and live outside this repo. Each decision's consequences live in
the doc that owns the topic; `OQ-n` ids name owner questions, which resolve in
the umbrella's question list, and `BL-nnn` ids name backlog items.

---

## Deployment topology

`cms` runs on a **cloud host**; `command-deck` runs on the **machine wired to
the test bench**, because it needs local USB/serial access. The deck connects
to the cloud database, so there is one authoritative dataset and no sync
problem.

Consequences for earlier notes:

- The port 8043 "collision" between profiles is not one — the profiles never
  share a host.
- "Single-tenant appliance, ownership is cosmetic" is wrong for the cloud cms,
  which needs per-user isolation. It holds for the deck's live telemetry
  topics, which serve one machine.
- The tester needs network reachability to the cloud host to run a test. No
  mitigation yet (OQ-61).

## Rejected, with the reason

| Proposal | Rejected because |
|---|---|
| Extract a `:shared` Gradle module | `:command-deck` is "cms plus hardware control", so being a runtime superset is the correct shape. The deployment split doesn't change what code each side needs. |
| Rename `SettingRepository` | It is a repository in the DDD sense; the store being `settings.json` rather than a table doesn't change that. |
| Restrict which Hilla services ship in the deck bundle | Deck is the full application. Role annotations are the access control, not packaging. |
| Authenticate `/api/ControllerEndpoint/**` | The hardware button box calls it without a session. File upload/download and the results export were moved behind authentication on 2026-10-09: the browser always sends the session cookie, and the export is owner-scoped. |
| Per-user filtering on STOMP topics | One deck drives one tester, so live force readings are shared between everyone watching that machine. Revisit if a deck ever fronts multiple testers. |
| Pin the Postgres image | Track upstream; handle a breaking major bump manually. |
| Fail fast without a mounted TLS cert | The self-signed cert generated by `startup.sh` is the intended operating mode — the tester is reached over a trusted local network. |
| Move `startup.sh` out of `cms/` | `:cms` is a hard Gradle dependency of `:command-deck`, so one shared entrypoint matches the module relationship. |
| npm/yarn workspaces | `pnpmEnable = true` hard-links from a shared store, so duplicated `node_modules/` trees don't cost duplicated disk. |
| Make `TestParameter.type` an enum | Users define their own parameter types in the UI and only three drive the runner; the free-form column is the feature. Using an unrunnable type faults the run, naming the type. **Superseded 2026-10-12** by owner decision D1: it is now the `TestType` enum ([`persistence-model.md`](dev/backend/persistence-model.md#testparametertype-is-an-enum)). |
| Migrate profile pictures to `FileMetadata` | The feature is being removed instead. |
| Bidirectional route merge | The cloud cms has no use for hardware routes that only work on the tester. |
| A shared-components package for `LogComponent` | Follows from keeping cms as the shared base — a direct cross-module import is consistent with that. |

## Accepted with a known cost

| Decision | Cost accepted |
|---|---|
| Flyway migrations in cms own the schema; both apps validate (reverses the earlier rejection of Flyway) | The bench embeds cms, so under `ddl-auto=update` a version skew let either app alter the shared schema. Cost: every entity change needs a hand-written migration that runs on both Postgres and H2. |
| Drivers implement the device contract themselves (device-api step 2; [device-api](dev/backend/device-api.md#steps-1-and-2)) | A contract change means `shadowJar` and a copy in both sibling repos before the deck can start on it; in return the deck references no driver class, even from a build file. The objections it answered: `usbmodbus` would not build on the installed JDK (then OQ-76; both repos now build from a clean checkout); the contract would become an artifact with no cheap way to share it (it is an included build the drivers `includeBuild`, so they compile against live source with no publish step); the `drivers` source set would survive for Spring's provider `@Component`s (each jar ships its own auto-configuration). |
| Keep `drivers/usbmodbus.jar` out of the repo | The shadow jar bundles two third-party vendor jars (`CommunicationLib.jar`, `ThesyconUSBLib.jar`, 2018) whose licence forbids redistribution. A fresh clone builds without it but cannot drive the machine. Splitting the vendor jars out so the project half could ship was declined (2026-10-18): not worth it while the private `usbmodbus` repo holds them anyway. |
| Fully untrack `generated/` | Anything building the frontend, CI included, must run the Hilla generator first. |
| Reconnect rather than abort on load-cell loss | A test can contain a gap. Gated by `deck.testrunner.recovery`, snapshotted per run; the gap shows as `runStatus` = `COMPLETED_WITH_GAPS` plus a `<millis>_gaps.json` sidecar. The force CSV stays byte-identical, so external tools see only a timestamp discontinuity. |
| Drop a transient driver fault rather than end the stream (OQ-74) | A run survives a load-cell glitch at the price of a hole no watchdog sees. Bounded per burst (80 ms), not per session — OQ-81. |
| Lower shut-off threshold and lower turn force are never negative, zero allowed (owner, 2026-10-13; was ≥ −rated capacity, OQ-89) | No run can target a compressive lower force; a saved row with a negative one is refused at its next save or run. |
| Destructive suction only after a break: LOWER crossing, peak ≥ lower + margin (bench setting, 500 N), motor stop confirmed or coasting; the 2 s clock guard is gone (owner, 2026-10-13) | An UPPER end never sucks, so a break exactly at the upper shut-off is missed; a clamp slip after load still sucks. An unconfirmed stop skips it with a log line, not a FAULT. [test-types](dev/backend/test-types.md#destructive-suction) |
| Shared rows (owner = null) are read-only for non-admins; anyone may create one (owner, 2026-10-13) | A non-admin who shares a row gives it away: afterwards only an admin can edit, delete or re-own it. Every write checks the *stored* owner, one unscoped `findById` per row. [security-and-tenancy](dev/backend/security-and-tenancy.md#the-checkusercanonlyaccessowndata-aspect) |
| Customers are owner-scoped; a shared project may only reference a shared customer (owner, 2026-10-13) | Existing customers were backfilled from their projects (`V4__customer_owner`): only a customer whose projects all share one owner got that owner, so a customer used across owners, or by no project, stayed shared — and read-only for non-admins. [security-and-tenancy](dev/backend/security-and-tenancy.md#the-checkusercanonlyaccessowndata-aspect) |
| Leave `optimizeBundle` off | Possibly a larger production bundle. Measure before flipping (OQ-16). |
| Tier 2 bounds its wait for the device in the deck: a `Device` lifecycle lock beside the monitor, given up at `RUN_EXCLUSIVE_WAIT_MS` (BL-212, 2026-10-18), not a `DriveProvider#open()` deadline in device-api | Two locks with one order (lifecycle lock, then monitor). Behind a `disconnect()` paying its ~5 s, tier 3 comes before a fresh stop could have run, and a second stop caller behind another's tier 2 gets a bounded false tier 3. An open() deadline was rejected: it bounds neither a `disconnect()` nor another tier 2, and a vendor open abandoned mid-enumeration risks the second session OQ-50 forbids. [safety-and-recovery](dev/backend/safety-and-recovery.md) |

## Test-runner redesign (OQ-64, owner 2026-10-12)

The structural refactor of drive, device and runner into the shape described in
[`test-execution-engine.md`](dev/backend/test-execution-engine.md). Decided before
the work started; the steps carried them.

| Id | Decision | Cost accepted |
|---|---|---|
| D1 | `test_parameter.type` holds **exactly the three runnable constants** (`TestType`); a foreign stored value is fixed by hand before deployment (`select distinct type from test_parameter` on the dev H2 and the cloud Postgres). Supersedes the free-form column above. | A row with any other value fails to load. |
| D3 | **Energize is one control-word write for every test type**, bench-checked as the stop's one-write rule was (H-06). Before, only time-cyclic wrote one word; cyclic and destructive wrote direction, general enable and start separately. | Behaviour change on the drive, owed a bench check. |

D2 assessed three items of the 2026-08 design against the code and **removed**
them — not deferred. Each row is the reason a re-proposal has to answer.

| Proposal | Rejected because |
|---|---|
| One-lock `DriveSession` with a revoking lease | The deck holds no drive lock: the driver gate bounds every drive call, a stop that misses its deadline sends tier 1 straight to tier 3, and tier 2 and `invalidateConnection` wait only on the `Device` lifecycle lock and monitor (`doc/dev/backend/safety-and-recovery.md`). A lease would be a further lock beside those and simplifies nothing. |
| `RefCounted<H>` device lifecycle | `Device` already is that type: the three refcount rules (count rises after a successful open, release clamps at zero, out-of-band loss keeps the holders' references and marks the handle lost so the next `connect()` re-opens, OQ-68) have one home, and both poll-thread joins are bounded. What would remain is a rename. |
| `SafetyGate` per run + `StopSequence` as data | The latch is per-incident, not per-run: a loss latches and a resume clears it inside one run, so `clearStopLatch` survives any split. `lastResult` serves concurrent stop callers (detector thread, loop, fallback). `ShutdownSafeStop` needs a stop with no run behind it. Thirty tests on the counted-stop guards and the stop-epoch fence would move for no removed rule. |

## Bench platform: Windows, native (owner, 2026-08-30)

The bench controller stays a Windows PC and `command-deck` runs natively on it
([`bench-deployment.md`](ops/bench-deployment.md)); both driver plugins are
Windows-only.

| Proposal | Rejected because |
|---|---|
| Rewrite the load-cell driver onto the DSCUSB's serial ASCII protocol (jSerialComm) for a Linux deck | Kept as a future option only. It would not remove the bench PC: the DSCUSB enumerates as `1781:0BAD`, which no Linux kernel driver binds out of the box, and the drive half needs a wiring change to the CFW11's RS485 terminals plus a serial Modbus stack whose bundled `purejavacomm` breaks on the pinned JNA. The protocol's continuous output mode is tracked on its own (OQ-80). |
